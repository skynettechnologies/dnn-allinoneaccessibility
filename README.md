## Requirements

| Requirement | Details |
| --- | --- |
| DNN Platform | **10.0.0 or later** (built and tested against DNN 10.3.3). DNN 9.x is not supported. |
| Persona Bar | `Dnn.PersonaBar.UI` - included in every DNN 10 installation. |
| .NET Framework | 4.8 (already required by DNN 10). |
| Web server | Windows + IIS, or Azure App Service. |
| Account | A **host (superuser)** account. Only hosts can install extensions. |
| Folder permissions | The IIS application pool identity needs **Modify** permission on the website folder (DNN needs this for every extension install). |
| Outgoing internet access | The **web server** must be able to make HTTPS (TLS 1.2) requests to `https://ada.skynettechnologies.us` - used by the settings page to register the domain and load/save settings. |
| Visitors' browsers | Must be able to load scripts from `https://www.skynettechnologies.com` (see the CSP / CORS section if you use a Content Security Policy or strict firewall). |
| Database | No new tables. Settings are stored in DNN's existing `PortalSettings` table. |
| web.config | **Not modified.** No theme/skin changes are needed. |

## Installation

The install package is `AllInOneAccessibility_01.00.00_Install.zip`. **Do not unzip it** - DNN installs the zip as it is.

> The **Create New Extension** screen in *Settings → Extensions* is only for writing a manifest by hand. Do not use it for this extension - use one of the methods below.

### Method 1 - Upload from the Persona Bar (recommended)

1. Log in to your DNN site as **host**.
2. Open the Persona Bar and go to **Settings (gear icon) → Extensions**.
3. Click **Install Extension** (top right).
4. Drag the zip onto the upload area, or click it to browse for the file.
5. **Package Information** - check the name (*All in One Accessibility®*) and version, then click **Next**.
6. **Release Notes** - click **Next**.
7. **License** - tick **Accept License**, then click **Next**.
8. **Installation Report** - the log should end with *Installation successful*. Click **Done**.

The page reloads and the widget is live on every page of every site.

### Method 2 - Available Extensions (copy the zip to the server)

Useful when uploads are blocked or the file has to be deployed by FTP / Remote Desktop.

1. Copy the zip (still zipped) into the DNN website folder at `\Install\Module\` - for example `C:\inetpub\dnn\Install\Module\`.
2. Log in as **host** and go to **Settings → Extensions → Available Extensions**.
3. Set **Showing** to **Modules**. *All in One Accessibility®* appears in the list.
4. Click **Install** next to it, then follow steps 5-8 of Method 1.

### Method 3 - Install all pending packages from the Install folder

1. Copy the zip into `\Install\Module\` as in Method 2.
2. While logged in as **host**, open `https://your-site/Install/Install.aspx?mode=installresources`.
3. DNN installs **every** package waiting in the `\Install\` folders and shows a status report. Click **Click Here To Access Your Site** when it finishes.

Use this only if you are happy for all other waiting packages in those folders to be installed too. Some hosts block `/Install/` URLs; if the page is not reachable, use Method 1 or 2.

### Method 4 - Include it in a brand-new DNN installation

1. Before running the DNN installation wizard, copy the zip into `\Install\Module\` of the new website.
2. Run the DNN installation as usual. The extension is installed together with DNN's own modules, so the widget is active as soon as the new site opens. (The same happens if the zip is in `\Install\Module\` when you run a DNN upgrade.)

### Upgrading or re-installing

- **Newer version**: install the new zip with any method above. There is no need to uninstall first - settings are kept.
- **Same version again (repair)**: with Method 1, tick **Repair Install** on the upload step when DNN says the package is already installed.

### Check that the installation worked

1. **Admin page**: open the Persona Bar → **Settings**. *All in One Accessibility®* is in the menu (log out and in again, or press Ctrl+F5, if it does not appear straight away).
2. **Front end**: open any page of the website in a private/incognito window. The accessibility icon appears in the bottom-right corner (or your chosen position).
3. **Page source** (optional): right-click the page → *View page source* and search for `aioa-adawidget`. You should find the widget script tag near the end of the page.
4. **Extension list**: *Settings → Extensions → Installed Extensions*, *Showing: Persona Bar* lists *All in One Accessibility®* with version 1.0.0.

## Configuration

To configure the widget, go to **Persona Bar → Settings (gear icon) → All in One Accessibility®**. The settings page opens inside the Persona Bar.

The first time the page is opened for a domain, the domain is registered for the free widget automatically and the default settings are loaded.

Available settings:

- Hex colour code of the widget
- Precise icon position (0-250 px from the left/right and top/bottom), or one of 8 preset positions
- Widget size (regular or oversize - oversize applies to desktop only)
- Icon type (29 icons)
- Icon size (5 sizes) or an exact custom size (20-150 px)

Click **Save Changes**. It may take a few seconds for changes to appear on your website. If you don't see the changes, clear your browser cache or check in a private browsing window.

**Multi-site installations**: each site (portal) has its own settings, keyed on the domain used to open the settings page. Open the settings page from each site's own domain to configure that site. The widget is added to all sites automatically.

**Who can see the settings page**: site Administrators and hosts.

## How it works

| Part | What it does |
| --- | --- |
| Front-end widget | On every page, the extension adds `<script id="aioa-adawidget" src="…/all-in-one-accessibility-js-widget-minify.js?colorcode=…&token=&position=…" defer>` just before the end of the page body. Popup windows (`popUp=true`) are skipped. |
| Persona Bar page | `Settings → All in One Accessibility®`, visible to Administrators and hosts. |
| Admin API | `/API/PersonaBar/AllInOneAccessibility/GetSettings` and `/SaveSettings`, protected by Persona Bar menu permissions and anti-forgery validation. |
| Settings storage | Full settings are stored by All in One Accessibility per domain. The colour and position used in the script tag are also kept in DNN portal settings (`AIOA_ColorCode`, `AIOA_Position`). |
| web.config | Not modified. |

## Content Security Policy (DNN 10)

DNN 10 can send a Content Security Policy header (configured in the Persona Bar security settings). It is off by default. If you turn it on, the extension automatically adds the page nonce to its script tag. If your policy lists allowed hosts instead, add the domains below to the relevant directives (`script-src`, `style-src`, `img-src`, `font-src`, `connect-src`, `frame-src`).

**CORS Policy Configuration**

To avoid CORS or CSP issues, ensure the following URLs are allowed on your website. These URLs should be added to your CORS/CSP configuration or trusted domains list.

| **Domain**                        | **Description**                           | **Usage**                        |
| --------------------------------- | ----------------------------------------- | -------------------------------- |
| https://\*.skynettechnologies.com | Skynet Technologies (Global Domain)       | API access and resources         |
| https://\*.skynettechnologies.us  | Skynet Technologies (US Domain)           | API access and resources         |
| https://\*.googleapis.com         | Google APIs                               | Services like Fonts, Translation |
| https://\*.gstatic.com            | Fonts APIs                                | Custom Fonts                     |
| <https://vlibras.gov.br>          | VLibras - Brazilian Sign Language Service | Sign Language                    |

**Instructions**

1. Update your server's CORS/CSP configuration to include these URLs.
2. Ensure wildcard subdomains (*) are supported where necessary.
3. Verify the application functionality by testing requests to these domains.
4. If issues persist, consult the documentation for CORS configuration guidance.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| **Install Extension** button is missing | You are logged in as an Administrator, not a **host**. Only hosts can install extensions. |
| Install fails with *Access denied* / *could not write file* | Give the IIS application pool identity **Modify** permission on the website folder, then install again. |
| Install says the package is already installed | Tick **Repair Install**, or install a higher version. |
| Install stops with a DNN version (core version) requirement error | The site runs DNN 9 or older. Upgrade DNN to version 10 first. |
| Menu item not visible after install | Log out and back in, press Ctrl+F5, or restart the site (*Settings → Servers → Restart Application*). |
| Settings page shows *Could not load the widget settings* | The web server cannot reach `https://ada.skynettechnologies.us` (firewall, proxy or no internet on the server), or the domain is a local test name (e.g. `dnn.local`, `localhost`) that cannot be registered. Test from the live domain. |
| **Save Changes** shows an error | Same as above - the server must reach `ada.skynettechnologies.us`. Check *Manage → Admin Logs* for details. |
| Widget does not appear on the website | View the page source and search for `aioa-adawidget`. If it is there, check the browser console for blocked requests (CSP, ad blockers, firewall). If it is not there, restart the application and check *Manage → Admin Logs* for errors. |
| Widget blocked by Content Security Policy | Allow the domains in the CSP / CORS table above. |
| Changes not visible after saving | Wait a few seconds, clear the browser cache or use a private window. |

## Uninstall

1. Log in as **host** and go to **Settings → Extensions → Installed Extensions**.
2. Set **Showing** to **Persona Bar** and find **All in One Accessibility®**.
3. Click the **delete (trash) icon**, tick **Delete Files**, and confirm.

This removes the widget from every page, the Persona Bar menu item, the DLL, the settings page files, and the stored `AIOA_*` settings. The domain registration on the All in One Accessibility side is not deleted.

## Building from source

Requirements: Visual Studio 2022/2026 with the **ASP.NET and web development** workload and the **.NET Framework 4.8 targeting pack**, and a local DNN 10 site (its `bin` folder provides the DNN assemblies).

1. Open `AllInOneAccessibility.sln`.
2. If your DNN site is not at `C:\inetpub\dnn`, change `DnnRoot` in the `.csproj` (or build with `-p:DnnRoot="D:\path\to\dnn"`).
3. Build in **Release**. The install package is created at `dist\AllInOneAccessibility_01.00.00_Install.zip`.
4. For quick testing after the package has been installed once, build in **Debug**: the DLL and Persona Bar files are copied straight into your local DNN site.

Project layout:

```
src/SkynetTechnologies.AllInOneAccessibility/
├── AllInOneAccessibility.dnn          DNN install manifest
├── Components/                        Widget script renderer, Skynet API client, settings store, app-start hook
├── Services/                          Persona Bar API controller (GetSettings / SaveSettings)
├── PersonaBar/                        Settings page: HTML, JS, CSS, resources, icon
└── Install/                           SQL scripts (uninstall clean-up)
```
